One order, three simultaneous exceptions

The original order is A → B. It changes to B → A → A after the first inspection. Part A0 fails the supplied quality check, and the first kit grasp receives an 8 cm target offset. The ALG.2 controller quarantines A0, detects the miss, retries, then fills the revised slots.

First evaluation seed (100), selected before evaluation. Both sides replay the recorded physical states at 1× simulated time; the shorter fixed-recipe run holds its endpoint. No object welds, mocap attachments or object pose edits during execution. This is a custom five-actuator Cartesian robot, not a humanoid or an industrial product model.

Compile the rules; observe the outcomes

The new general-purpose compile_schedule / compileSchedule API lowers an acyclic prerequisite graph to a portable readiness circuit. The kitting example composes it with inventory matching. The compiled circuit selects eligible work; host code chooses among eligible tasks, checks physical outcomes and executes the authored motion stages. The neural substrates execute supplied operations—this does not train a pretrained transformer to discover the workflow.

A concrete commercial wedge: exception-aware kitting
Recipe changeover
Change order sequence and quantities in JSON while retaining motion skills. The pilot question is how much operator programming and retraining time this removes.
Recoverable faults
Detect failed picks before recording fulfilment. Measure manual interventions per 1,000 orders and the time spent recovering.
Traceable acceptance
Link each dispatch to quality, dependency and placement evidence. Measure wrong-SKU and rejected-part escape rates independently.


Measured here: 42 correct ALG.2 orders, 24 automatic retries and no false completion receipts. Not measured: real throughput, downtime, staffing, deployment costs, learned visual quality, machinery integration or financial return. Simulated durations omit sensing latency, conveyors, scanning, packaging, resets and operator work. “Seal” in the trace means logical order release, not physical carton sealing.


The next qualification step is a customer-provided SKU/order distribution, a real pose and inspection pipeline, and paired trials against the customer's existing feedback automation. Compare an actual VLA or diffusion policy with and without this supervisor under equal observations, skills and fault schedules. Hardware acceptance must include unknown items, sustained failed grasps, sensor errors and order changes during a transfer; those are outside this experiment.
