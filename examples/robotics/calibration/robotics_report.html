Yes—the bounded framework and robot example are done.

The implemented scope includes a shared tensor algorithm format, a Python source frontend and builder, symbolic execution, differentiable circuits, scheduled attention execution, trained-weight export, explicit recurrent state, conversion checks, and structural attention-bias adapters. Python is the reference implementation; TypeScript executes shared artifacts across the three substrates.

The performance gain comes from the learned actuator correction. Attention did not outperform the symbolic executor. It provided a differentiable execution substrate that we could train and convert back. We have not demonstrated automatic problem recognition or execution of this controller inside a pretrained transformer.

02 / Why it improves

Correct the actuator model; preserve the controller

τ = clip[30(q* − q) + 2.5(v* − v) + τbias + a·v + b·tanh(5v) + c, −8, 8]

The simulator applies a synthetic opposing actuator force. Calibration labels give the correction needed to counter it. We supply the functional form; training fits its 60 coefficients. This is a small, inspectable learning problem—not discovery of the equation itself.

Training

500 Adam steps

128 velocity vectors, 20 joints each. Training through ALG.2; seed 17. Coefficients start at zero.

Calibration check

128 held-out vectors

Seed 1701; slightly wider velocity range. Correction MSE: 3.57 × 10⁻⁹ versus 0.294 for zero correction, in squared torque units.

Simulation check

Six frozen-policy runs

Nominal baseline; corrected ALG.0/1/2; shifted baseline and corrected ALG.2. No online updates in the rollouts.

03 / What the framework adds

The improvement survives the round trip

Hard ALG.2: operand routing

Each operation retrieves input registers using actual scaled dot-product attention. A compiler-generated mask selects one source per argument. The declared local operation then executes, following the supplied schedule.

Arithmetic and scheduling are supplied. This is not an arbitrary program embedded solely into ordinary pretrained transformer weights.

Conversion checks

Across 32 sampled cases, maximum output difference was 4.44 × 10⁻¹⁶ for ALG.1 and ALG.2 versus the symbolic reference. Hard ALG.2 → ALG.0 export matched with zero measured difference.

Empirical checks at specified tolerances, not proofs for every input. Nominal closed-loop rollouts also produced matching tracking metrics.

04 / Pretrained-transformer integration

Algorithm structure can bias QK interactions

The adapter owns separate query/key binding networks, an edge-free null slot, role-specific strengths and copied pretrained Q/K/V/O projections. In the 50-token CLIP check, zero-bias output error was 0; relation-strength gradient L1 norm was 6.25 × 10⁻⁶; nonzero bias changed output by 7.03 × 10⁻⁴.

This is integration evidence, not a better-than-baseline task result. Bindings are initially untrained. There is no demonstrated context-based problem identification or robot control inside CLIP. Attention adjacency alone also does not establish a probabilistic Bayesian-network interpretation.

The control result uses one morphology, one calibration seed and two six-second conditions. Supervision comes from the same authored disturbance family used in simulation. There is no comparison to analytic compensation, a tuned baseline, a generic MLP residual or reinforcement learning. This demonstrates the conversion-and-training workflow, not a new best controller.
