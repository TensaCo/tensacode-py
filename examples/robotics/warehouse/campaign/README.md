# Bounded experiment queues

`python -m examples.robotics.warehouse.campaign.run queue.json --output /tmp/campaign/lane0`
executes argument-list commands sequentially on the current machine. Use the same
module through SSH for a peer lane. A lane is a disjoint CPU set coordinated across
workers; keep the union below 80% of available CPUs. One CUDA job per host is the
campaign scheduling policy. Queue commands and source files are reviewed before
launch, not generated by an untrusted model.

```json
{
  "cwd": "/absolute/frozen/checkout",
  "cpus": [0, 1, 2, 3],
  "memory_gib": 12,
  "deadline_utc": "2026-10-16T23:54:00+00:00",
  "jobs": [{
    "id": "seed0",
    "backend": "egl",
    "command": ["/absolute/python", "experiment.py", "--seed", "0"],
    "sources": ["experiment.py"],
    "timeout_s": 1200,
    "protocol": {"split": "development", "seed": 0}
  }]
}
```

Each job has a systemd CPU quota, no swap, a RAM ceiling, `taskset` affinity, and a
systemd runtime deadline that survives worker termination. CPU utilization above
75% pauses the owned job until below 60%; GPU jobs use the same utilization guard.
Available system RAM below 25% stops the job. Start waits for 35% available RAM.
These are sampled guards, not guarantees against momentary outside-workload
spikes. The worker never stops another user's jobs. CUDA requires `mps_pipe`
pointing to a separately created, owned private MPS directory and requests 70%
active threads. EGL has no equivalent hard GPU partition: use measured low-load
rendering and the sampled guard. NVIDIA utilization/memory instrumentation may
not expose all unified-memory details; `/proc/meminfo` tracks available system RAM.

`ledger.jsonl` records command, host, source SHA256, protocol, resources, and outcome;
per-job `resources.jsonl` is fsynced every sample. Finished IDs are skipped on resume,
including failures, so failures are retained rather than silently retried. Use a new
ID for an explicitly reviewed retry. Do not reuse an output directory for a different
protocol. `stdout.log` retains process output. Exit zero is process success only;
scientific task success must come from the independent experiment validator.

A real host smoke found `AllowedCPUs` alone did not change the child process's
`sched_getaffinity`. `taskset` is therefore applied as well as the cgroup property;
a second smoke confirmed the exact requested singleton CPU set. Earlier experiment
resource records are not retroactively rewritten.

For newly launched workers, create `OUTPUT/pause-admission` to finish the current
job and pause before the next one. Remove that file to resume. The deadline remains
active while admission is paused. This feature was added after the first immutable
teacher queue snapshot; that earlier queue used externally paused workers with
separate resource watchers during diagnosis.

New workers also hold `/tmp/tensorcode-campaign-gpu.lock`: EGL jobs share a lease,
CUDA jobs require an exclusive lease. Thus a CUDA model window cannot overlap an
EGL rendering window on the same host. Existing workers launched before this
revision are managed through explicit admission pauses until drained. MPS's reported 32/48 equivalent SM
limit bounds CUDA execution allocation, without reserving dedicated physical SMs
or partitioning memory bandwidth; NVIDIA's utilization percentage measures
busy time and is a different quantity. Earlier concurrent work briefly sampled94%
GPU utilization and triggered the guard; that observation is retained, not recast as
a guaranteed80% utilization ceiling. Current policy forbids CUDA/EGL overlap.

A native simulator that mixes CUDA inference with RTX/OptiX graphics must set
`gpu_busy_guard: true` on its job. MPS does not bound the graphics workload; this
option additionally pauses the whole owned unit above 75% sampled GPU busy time
and resumes below 60%. Those pauses count against the job and campaign deadlines.
Use `cuda_probe_python` to verify the CUDA context with the job's actual runtime.
