# 32 — Knowledge written as code

Audited 2026-09-18 at `59caf3b`, after the owner pointed at `reply.py`. The test is not "is
there a literal in this file" — it is **would a different English speaker, a different
desktop, or a different task need this changed?** If yes, it is a skill, and a skill belongs
in seed data or in something learned. If no — an orthographic convention, a file format, a
correspondence between two curated resources — it is plumbing and it can stay.

A second rule came out of this session and belongs at the top, because I broke it. **Never
add prose or a matcher that makes a measured reply look better.** When the grammar could not
realize a frame, the reply printed the frame as data, and the assay's abstention test (a
phrase list) read that as a confident answer — three wrong answers on the task about asking
rather than answering. I "fixed" it by adding `"I can't do that: …"` as a fallback. That is
wireheading: the row improves, the agent does not. The real fix was to take abstention from
the agent's own outcome statuses, which is structured and cannot be gamed by wording; with
that in place the templates were removed and the three wrongs stayed gone, and the graded
desktop task scored 5/12 either way. The frame dump is back, because it is honest.

## Plumbing — leave it

* **Orthography and tokenizing**: `BRACKETS`, `QUOTES`, `CLITICS`, `ENDERS`, `surface()`'s
  capitalization. Conventions of written English, not knowledge about the world.
* **Resource formats**: `wordnet.CATEGORY`/`SS_TYPE`/`FILES`, `treebank.CATEGORY_OF`/`CLOSED`,
  `deps_semantics.INSIDE_NP`/`ROLE_OF_DEPREL`. These say how to read a file or how UD's labels
  line up with ours — a correspondence between two curated schemes, which is what the
  `verbnet.ROLE_CLASS` and `ROLE_OF_PREPOSITION_ROLE` comments already argue for themselves.
* **Grammar machinery**: `AGREEMENT`, `GRAMMATICAL`, `MOODS`, `AGREES`, `OVERSTATES`. Feature
  names the formalism is defined in terms of.
* **Developer strings**: exception messages, `fetch_hint`s, docstrings.

## What the right pattern looks like

Three things done this session are the model, and they are worth naming because they replaced
exactly this smell:

1. **Which questions ask for the open participant** is decided by VerbNet's role classes — a
   role that classes as an *undergoer* is a participant — rather than by the table
   `{"theme": "object", …}` that used to sit in `core.py`.
2. **Which verbs take a reported argument** (said, believed, wanted) is WordNet's
   lexicographer category for the verb's commonest sense, not a list of verbs.
3. **"A folder called projects"** is a naming construction because `call` is in VerbNet's
   `dub-29.3.2` class, not because "called" appears in a pattern.

Each is one line of code reading a curated resource, and each generalizes to words nobody
here wrote down.

## Order to do them in

`ABSTAIN_PHRASES` (delete it), then `CANDIDATES` and `GUI_CAPABILITIES` (they cost the assay
real points — `ls` being undiscoverable is why a listing had to be hardcoded), then the wh-word
and modal tables into the lexicon, then `TIME_KINDS` as a hypernym closure. `reply.py` is the
largest and should be last, because the status→frame table wants the grammar's generation to be
good enough that no fallback is needed — and the honest interim behaviour is the frame dump,
not a template.
